# ADR 0004 — 업로드 크리덴셜은 티켓 경로 + 코드 두 조각으로 나눈다

- 상태: 채택
- 날짜: 2026-07-26

## 맥락

게스트 업로드 티켓([ADR 0001](0001-write-only-guest-upload.md))를 어떻게 전달할 것인가. 두 안이 있었다.

**(가) 하나의 비밀, 두 개의 전달 경로.** 링크에 비밀이 통째로 들어 있고(`/u/K7M29XPQ`) 같은 값을 폼에 직접 칠 수도 있다. 링크를 누르면 바로 업로드할 수 있다 — **링크 자체가 열쇠**다.

**(나) 문패 + 열쇠, 둘 다 필요.** 티켓 경로는 페이지 위치만 가리키고, 인증은 별도 코드로 한다. 둘 다 맞아야 올라간다.

설계 중에 (가)를 채택했다가 (나)로 정정했다. (가)를 고른 근거는 전달 편의였다 — 보낼 것이 하나뿐이고 타이핑이 적다.

## 결정

**(나)를 채택한다.**

- 티켓 경로 4자: `https://<서버>/u/AB3K`
- 코드 8자: `K7M2-9XPQ`
- 둘을 함께 전달하고, 업로드하려면 둘 다 맞아야 한다

## 근거

**URL은 새기 쉬운 물건이다.** 메신저 미리보기 서버가 GET으로 가져가고, 브라우저 기록에 남고, 리버스 프록시 액세스 로그에 박히고, referrer 헤더에 실린다. URL 하나에 업로드 권한을 담으면 그 전부가 크리덴셜 유출 경로가 된다.

코드를 폼 본문으로 분리하면 **URL만 캡처하는 경로가 전부 무력해진다.** 링크와 코드를 같은 메신저 메시지로 함께 보내더라도 그렇다 — 미리보기 봇은 URL을 GET할 뿐 메시지 본문의 코드를 POST하지 않는다.

**고정 엔드포인트가 없다.** URL에 조각이 들어가므로 `/u` 같은 고정 페이지가 없고, 스캐너가 "게스트 업로드가 열린 teledrop 인스턴스"를 지문 식별할 수 없다.

**엔트로피 배분이 목적에 맞다.** 4자(2^20) + 8자(2^40)로 합쳐 2^60이다. 티켓 경로가 짧아도 되는 것은 그것이 단독 비밀이 아니기 때문이고, 짧아야 하는 것은 S3-a(낯선 PC에서 주소창에 직접 입력)를 위해서다.

## 결과

- 상대에게 두 개를 보내야 한다. S1에서 친구는 클릭 후 8자를 입력하고, S3-a에서는 URL과 코드를 모두 친다. (가)보다 타이핑이 많다 — 감수한다
- **방어를 티켓 코드가 전담한다.** 티켓 경로는 열거될 수 있으므로 **코드 시도 횟수 제한(10회)이 필수**다. 넘으면 그 티켓을 죽인다
- **경로 열거는 막지 않는다.** 없는 티켓 경로에는 404를 낸다. 경로가 비밀이 아니라고 선언한 이상 살아있는 경로를 숨기는 것은 앞뒤가 안 맞고, 실익도 없다 — 공격자가 살아있는 티켓을 전부 찾아내도 각각 10번씩 던질 수 있을 뿐이고 코드는 2^40이다. 숨기면 주소를 잘못 친 사용자가 "코드가 틀렸다"는 엉뚱한 메시지를 보는 비용만 남는다
- 액세스 로그 마스킹의 중요도가 내려간다. 로그에 남는 것은 티켓 경로뿐이고 그것만으로는 아무것도 못 한다

## 기각한 근거

(가)를 밀었던 "보낼 것이 하나뿐이라 편하다"는 유효한 이점이지만, 위협 모델과 맞바꿀 만큼은 아니다. write-only에 시한부에 1회 소진인 크리덴셜이라 유출 피해가 제한적이라는 것이 (가)의 논거였는데, **유출 경로가 URL 하나에 몰려 있다는 점이 그 계산에서 빠져 있었다.**
